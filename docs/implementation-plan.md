# MeetingOS 开发方案与执行记录

2026-10-12。用户授权：充分尽调、选择经典设计／UI 实践、自行定方案并开始开发。生产部署、SSH 设置仍未恢复授权。

## 决定

- 主界面采用本轮生成的第一张浅色会议工作台：256px 左侧会议导航、主记录区、持续可见的建议区。正文 14–16px，蓝色主操作，简单分隔。桌面双栏，手机单栏切换并保持主要操作可达。
- 两个模式：内部计划评审、客户辅助。AI 输出默认私有，明确采纳后才成为共享决定；客户展示与客户版导出不读取私有建议／底线。
- 默认由网站保存会议，没有个人 Agent 的人也可以注册／登录使用。个人 Agent 接入是可选项。
- 仓库根目录作为开发入口；本地历史源码保留在 `source-snapshots/local-20261011`，原服务器 91 个文件另存 `source-snapshots/server-20261011`。
- Node 24 原生 SQLite，事务、唯一事件 ID、版本化修订、完整原文、分页及可回放变化流。单实例内部部署先不引入 Redis／独立数据库服务。
- 人类登录使用 HttpOnly Cookie；Agent 使用可撤销、可到期、可限定会议及权限的令牌。个人记录按账号隔离。生产注册需要内部邀请码。
- 一个上下文服务，读取目标／简报、已允许的私有约束、附件事实、原稿／修订及此前建议。人工求助优先；自动触发独立去重／防并发，不沿用一分钟周期门控。
- 模型未配置／调用失败时明确返回错误，不生成貌似 AI 的本地模板。保存、文本输入和授权 Agent 写入仍可用。
- 第一版交付 REST、实时事件与 Hermes Skill；如实现 MCP，明确协议与认证范围，不把自定义令牌称为完整 OAuth 方案。

## 尽调依据与限制

直接读取官方 GitHub 源码／文档：Microsoft Fluent UI、Jitsi Meet、LiveKit Agents／React starter、Meetily、Open WebUI、MCP 2025-11-25 授权规范。Meetily 的分栏、分页、SQLite schema 和 LiveKit 的会话／Agent 分离状态已实际读取。README 中的商业宣称不当作实测结论。

Otter、Granola、Teams 商业网站在本次云策略下返回代理 403；相关官方域名已保存到环境草稿，需要用户在环境设置审核、保存并发布。不会用其他代理绕过限制，也不声称已经审核这些产品的最新登录界面。
