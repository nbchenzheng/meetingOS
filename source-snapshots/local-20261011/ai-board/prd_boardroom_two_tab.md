# 增量 PRD：会议室「三栏」→「发言区 / 智能纪要」双标签重构

> 范围：仅前端布局与组件重组。不改动后端、不新增接口、不重写现有组件。
> 复用组件：`TranscriptPanel` / `MindMap` / `CommentaryPanel`。
> 参考：飞书妙记（标签栏简洁；发言区 = 字幕流，智能纪要 = AI 纪要）。

---

## 1. 变更目标

移除 `BoardRoom` 中段 `.board-split` 的三栏并列布局，改为「顶部标签栏 + 单一内容区」的双标签结构（**发言区** / **智能纪要**），降低三栏同屏的信息过载与窄屏挤压；发言区聚焦麦克风发言与大咖 AI 发言的合并时间线，智能纪要聚焦 AI 整理版、思维导图与实时点评三类 AI 产出。

---

## 2. 用户故事

- **US1（切换）**：作为会议参与者，我希望在会议室用「发言区 / 智能纪要」两个标签切换，以便在一屏内专注查看实时字幕或 AI 纪要，而非被三栏分割的界面干扰。
- **US2（发言区看合并时间线）**：作为会议参与者，我希望在「发言区」看到麦克风发言（speech）与大咖 AI 发言（opinion）按时间顺序合并成一条时间线，并保留「正在识别…」临时提示，以便像看字幕一样连续阅读全场讨论。
- **US3（智能纪要 · 整理版）**：作为会议参与者，我希望在「智能纪要」中看到 AI 整理版全文及其状态（生成中 / 最近整理于 / 暂不可用），以便快速获取结构化结论。
- **US4（智能纪要 · 导图）**：作为会议参与者，我希望在「智能纪要」中看到思维导图及其更新状态，以便把握讨论的知识结构。
- **US5（智能纪要 · 点评）**：作为会议参与者，我希望在「智能纪要」中看到实时点评流（可静音 / 收藏 / 定位），以便随时查看大咖与 AI 的即时反馈。

---

## 3. 需求池

### P0（必须）

- **P0-1**：移除 `.board-split` 的三栏并列（transcript-col / mindmap-col / commentary-col），改为「顶部标签栏 `tab-bar` + 单个内容区 `tab-panel`」结构，含两个标签「发言区」「智能纪要」。
  - *验收*：DOM 不再存在三栏并列的 flex 子项；存在 `tab-bar` 与 `tab-panel` 容器；两个标签文案分别为「发言区」「智能纪要」。

- **P0-2**：「发言区」内容 = 麦克风 speech + 大咖 opinion 的合并时间线，按 `ts` 升序（复用 `TranscriptPanel` 现有 `buildParagraphs` 合并逻辑），强制 `view="raw"`，移除「原稿 / 整理版」切换。
  - *验收*：复用 `TranscriptPanel`（view=raw、refinedText 置空），不渲染 view-switch；时间线与现状 raw 视图一致；opinion 段显示「💬 姓名」头。

- **P0-3**：保留 `interim`「正在识别…」临时提示（附在最新 speech 段末；仅有 interim 时显示独立占位）。
  - *验收*：收音中且存在 interim 时，发言区可见「正在识别… {interim}」提示。

- **P0-4**：「智能纪要」内容 = 「AI 整理版区块」+「思维导图区块」+「实时点评区块」三区块竖向堆叠（默认顺序：整理版 → 思维导图 → 实时点评）。
  - *验收*：三区块均出现且竖向排列；分别渲染 `refinedText` / `MindMap` / `CommentaryPanel`；数据来自 `useTranscriptEnhance` 与 `useLiveCommentary`（经 `mergedCommentaries`），不做二次处理。

- **P0-5**：「AI 整理版」区块展示 `refinedText`；为空时显示「AI 整理版生成中…」；展示整理状态（整理中 / 最近整理于 HH:MM / 整理暂不可用）。
  - *验收*：`refinedText` 存在显示全文；为 null 显示占位；状态文案与现有 `enhance-statusbar` 逻辑一致（refining→整理中；lastRefineAt→最近整理于；refineError→整理暂不可用）。

- **P0-6**：「思维导图」区块展示 `MindMap`（root=mindmap），并展示导图状态（生成中 / 更新于 HH:MM / 暂无导图）。
  - *验收*：状态逻辑与现有 mindmap-col 状态条一致；`mindmap` 为 null 时显示 MindMap 自带空态（「暂无思维导图…」）。

- **P0-7**：「实时点评」区块复用 `CommentaryPanel`，传入 `mergedCommentaries`、`commentaryEnabled`、`live.collecting`、`live.error`、`setCommentaryEnabled`、`handleAnchor`。
  - *验收*：点评流、静音开关、收藏 / 定位交互与现状一致。

- **P0-8**：默认进入「发言区」标签；切换标签不丢失已累积的转录 / 点评数据。
  - *验收*：首次进入为发言区；在发言区发言若干条后切到智能纪要再切回，发言区内容完整保留。
  - *实现提示*：所有数据（entries / refinedText / mindmap / mergedCommentaries / live.commentaries）均在 `BoardRoom` 上层 hook 持有，组件卸载-重挂不会丢数据。**已确认采用：两个 tab-panel 同挂载、用 `visibility` 切换可见性（非 `display:none`、非条件渲染卸载）**，可同时保留 `CommentaryPanel` 本地 UI 态（收藏 / 忽略 /「新」标记）与滚动位置，并消除 P0-8 的卸载重置风险（设计决策 (B)）。

- **P0-9**：`topbar`（返回 / 结束会议 / MicControls / BriefPill）、`controls` 提示条、`BigShotBar`（大咖条含「💬 发言」）、`NewBigShotModal` 完全保持不变。
  - *验收*：上述组件 props 与位置与现状一致，无改动。

- **P0-10**：点击「智能纪要」中点评的「@关联 · 定位」时，自动切换到「发言区」标签并执行现有滚动高亮（`handleAnchor` 逻辑保留）。
  - *验收*：在智能纪要点击定位 → 自动切到发言区 → 对应段滚动并高亮约 2.2s。

### P1（应该）

- **P1-1**：标签激活态有清晰视觉区分（激活标签蓝渐变填充 + 白字，参考现有 `.view-switch .seg.on` 观感）；支持键盘可达（button 或 `role=tab` + `aria-selected` / `aria-controls`）。
  - *验收*：当前标签高亮明显；hover / 聚焦有反馈；可用键盘聚焦与切换。

- **P1-2**：移动端（≤720px）标签栏与内容自适应：标签栏横向占满可点；内容区单列填充，不再出现三栏并列。
  - *验收*：≤720px 下不出现三栏；标签栏可点；单个内容区占满可用高度。

- **P1-3**：「智能纪要」三区块在桌面端采用明确的滚动模型（整页单滚动容器 / 各区块独立内部滚动，二选一），区块间有清晰卡片分割（复用 `.enhance-statusbar` / `.glass` 视觉）。
  - *验收*：区块边界清晰；滚动行为明确且不互相遮挡。

- **P1-4**：标签切换有轻量过渡（淡入 / 高度过渡），避免内容突跳，且不影响数据。
  - *验收*：切换时内容有可见过渡。

### P2（可延后）

- **P2-1**：发言区顶部保留轻量「实时转写中」指示（小圆点 / 脉冲），与 `controls` 提示条呼应。
  - *验收*：收音中时发言区顶部有可见「转写中」指示。

- **P2-2**：标签选择记忆（会话态或 localStorage），下次进入默认上次标签。
  - *验收*：重进会议保留上次标签（可选）。

- **P2-3**：智能纪要内提供轻量操作（回到顶部 / 复制整理版等）。
  - *验收*：至少提供一个便利操作。

## 4. UI 设计稿（结构化描述 + ASCII）

### 4.1 整体布局

```
┌──────────────────────────────────────────────────────────┐
│ topbar:  ←准备   结束会议   [MicControls]        [BriefPill] │  ← 不变
├──────────────────────────────────────────────────────────┤
│ tab-bar:  [ 发言区 ]  [ 智能纪要 ]                          │  ← 新增（激活态高亮）
├──────────────────────────────────────────────────────────┤
│ tab-panel（单一内容区，高度 = 剩余空间，可滚动）            │
│                                                            │
│   ── 发言区激活 ──                                         │
│   <TranscriptPanel view="raw" />  （合并时间线 + interim） │
│                                                            │
│   ── 智能纪要激活 ──                                       │
│   ┌─ 区块1 · AI 整理版 ───────────────────┐              │
│   │ 状态条: 整理中 / 最近整理于… / 暂不可用   │              │
│   │ [refinedText 或 “AI 整理版生成中…”]      │              │
│   └────────────────────────────────────────┘              │
│   ┌─ 区块2 · 思维导图 ───────────────────┐              │
│   │ 状态条: 生成中 / 更新于… / 暂无导图      │              │
│   │ <MindMap root={mindmap} />              │              │
│   └────────────────────────────────────────┘              │
│   ┌─ 区块3 · 实时点评 ───────────────────┐              │
│   │ <CommentaryPanel … />（开关 / 收藏 / 定位）│            │
│   └────────────────────────────────────────┘              │
├──────────────────────────────────────────────────────────┤
│ controls 提示条  ← 不变                                     │
└──────────────────────────────────────────────────────────┘
        ┌────────────────────────────────────┐
        │ BigShotBar（大咖条 + 💬发言）  ← 不变  │
        └────────────────────────────────────┘
```

### 4.2 标签栏（tab-bar）

- 位置：紧贴 `topbar` 下沿，横向排列两个按钮（`role=tab`）。
- 视觉：未激活为次级文字色 + 透明底；激活为蓝渐变填充（复用 `.view-switch .seg.on` 观感）+ 白字；可加底部 2px 指示条。
- 可达性：激活标签 `aria-selected="true"` + `aria-controls` 指向对应 `tab-panel`。

### 4.3 发言区（tab: 发言区）

- 单一 `TranscriptPanel`（view=raw、refinedText 置空、保留 `interim` / `anchorEntryIds` / `anchorTs`）。
- 复用现有段落渲染：speech 按停顿聚合、opinion 单段带「💬 姓名」头、最新段 `latest` 高亮、interim 附最新段末。
- 移除现有 `transcript-col` 顶部 `view-switch`（原稿 / 整理版切换）与「整理版」按钮。

### 4.4 智能纪要（tab: 智能纪要）

- 三个「卡片区块」竖向堆叠，区块间距 10–14px。
- **区块1（AI 整理版）**：顶部状态条（复用 `.enhance-statusbar` 样式，文案见 P0-5）；主体为 `refinedText`，空态占位「AI 整理版生成中…」。
- **区块2（思维导图）**：顶部状态条（文案见 P0-6）；主体为 `MindMap`，空态由组件自带（「暂无思维导图，会议进行数分钟后将自动生成」）。
- **区块3（实时点评）**：直接放 `CommentaryPanel`，其内部已有标题 / 开关 / 计数 / 采集态 / 降级提示头，无需再包状态条；保留 `onAnchor={handleAnchor}`。

### 4.5 移动端（≤720px）

- `tab-bar` 横向占满、两标签可点；内容区 `flex:1` 占满，单列显示当前标签内容。
- 智能纪要三区块在窄屏下竖向排列（整页滚动，或各区块给定 `min-height` 独立滚动，待确认 P1-3）。

## 5. 待确认问题

### 5.1 已确认决策（架构拍板，设计 §8.2）
1. **三区块顺序**：保持「整理版 → 思维导图 → 实时点评」（与 PRD 默认一致）。
   - 决议：不改顺序；暂不引入折叠 / 拖拽排序。
2. **智能纪要滚动模型（桌面）+ CommentaryPanel 本地态**：选定方案 (B) —— 智能纪要 tab-panel 自身不滚动，三区块各自独立内部滚动；`CommentaryPanel` 零改动，其本地 UI 态（pinned/ignored/seen/newIds）与滚动位置因「两 tab-panel 同挂载、用 `visibility` 切换可见性（非 `display:none`、非条件渲染卸载）」天然保留。
   - 决议：同时落实 P0-8 与 P1-3；消除卸载重置风险。
3. **跨标签定位（P0-10）**：`handleAnchor` 签名不变，内部在设置 `anchorEntryIds`/`anchorTs` 之后追加 `setActiveTab('speech')`，配合同挂载机制在发言区可见后触发高亮滚动。
   - 决议：确认自动切换 + 高亮。
4. **发言区跳转按钮**：完全移除原稿 / 整理版切换入口；发言区恒为 raw；整理版仅在智能纪要标签内可见。
   - 决议：不在发言区暴露任何「整理版」入口。
5. **移动端 min-height**：整理版 160px / 思维导图 200px / 实时点评 220px（点评沿用现有 `.commentary-col` 基线）；三块独立内部滚动、tab-panel 不整页滚动，避免裁剪。
   - 决议：落实 P1-2；固定 min-height。

### 5.2 仍待确认（次要实现 / 可达性细节，已记入设计 §8.2）
- **空态文案精确度**：整理版空态沿用 PRD P0-5 的「AI 整理版生成中…」；思维导图沿用 `MindMap` 自带「暂无思维导图…」；点评空态沿用 `CommentaryPanel` 现有文案。实现时逐字对齐，避免新增不一致措辞。
- **过渡时长**：产品建议 ≤250ms、ease-out、纯视觉（不影响数据），与 P1-4「轻量过渡」一致。
- **移动端 tab-bar 换行策略**：两标签（发言区 / 智能纪要）正常宽度不换行；建议 `nowrap` 且两标签常驻（等宽或左对齐），极窄屏允许横向滚动，绝不隐藏任一标签。
- **inert 兼容性**：隐藏的 tab-panel 须从 Tab 键序与读屏中移除——`visibility:hidden` 已使子树不可聚焦且不宣报，配合 `aria-hidden` 即可；需确认低端浏览器对 `visibility` 焦点行为的覆盖。
- **标签状态持久化（原 §5-6 / P2-2）**：维持默认「每次进入停发言区」，暂不持久化（可后续作为 P2 增强）。
