# 虚拟私董会（Virtual Board）· 方案与设计

> 版本：v0.1 方案稿（待确认）
> 日期：2026-07-08
> 目标：日常公司高层开会时打开网页，麦克风实时语音转文字，多位"大咖"AI 角色基于**项目进展 + 实时会议内容**自动/手动给出董事会式意见。

---

## 一、产品定位与场景

**一句话**：把会议室变成"董事会现场"——人类高管开口讲，网页把话实时转成文字，几位萃取自真实经验的"大咖"角色像董事一样随时插话、给判断、提风险。

**典型流程**
1. 开会前：录入**项目简报/进展**（目标、阶段、痛点、当前进展、关键数字）。
2. 开会时：打开网页 → 点"开始收音" → 麦克风实时转写，字幕流滚动。
3. 大咖**自动发言**：转写累积到阈值（如每 60s 或话题切换），最相关的 1–2 位大咖基于"项目进展+最近发言"给出意见。
4. 大咖**手动发言**：点击大咖头像下的「发言」按钮，立即强制该角色基于当前上下文表态。
5. 散会：自动沉淀**意见纪要 + 证据链 + 待办**，可导出 PDF/Markdown。

**与 FDE 答辩工作台的关系**：私董会 = 答辩工作台的"会议化改造版"。复用其转写内核与角色内核，把"评委提问/评分"改造为"董事发言/决议"。

## 三、系统架构

```
[会议室麦克风]
      │ getUserMedia (HTTPS/localhost 安全上下文)
      ▼
[浏览器前端 React]  ──WebSocket(/ws/board/transcribe)──► [Node 服务端 asr-service]
      │                                                      │ 阿里云实时 / OpenAI-compatible ASR
      │                                                      ▼
      │                                             流式逐句文本 → 回传前端字幕流
      │                                                      │
      ▼                                                      ▼
[会议上下文] ←─ 项目简报 + 实时转写累积 ──────────────► [LLM Router]
      │                                                      │ OpenAI-compatible 真实模型
      │                                                      ▼
[私董会圆桌 UI] ◄── 大咖意见(流式/整段) ◄────────── [大咖发言生成]
   · 大咖头像卡 + 「发言」按钮                               （prompt = 角色persona + 关注点 + 上下文）
   · 实时字幕流
   · 当前发言详情 / 项目简报面板
      │
      ▼
[纪要沉淀] → SQLite → 导出 Markdown / PDF
```

- **前端**：React + Vite + TypeScript（沿用 FDE，零额外学习成本）。
- **后端**：Node 内置 HTTP + WebSocket（`ws`）+ SQLite（沿用 FDE）。
- **无 Key 兜底**：ASR/LLM 未配置时，自动回退"本地规则"（保证 demo 永不开天窗）。

## 四、核心界面与交互设计

### 4.1 布局（会议进行态）· 上下分栏
> 用户确认（2026-07-08 16:14）：采用**上下分栏**。实时字幕流在最上方、占大面积（会议焦点）；大咖头像/名称/意见反馈在下方一整条。

- **上半区 · 实时字幕流（约 65% 高度，大面积）**：整屏顶部大区域。麦克风状态 + 音量条常驻角落；逐句转写大字滚动、可编辑/标记；最新一句左侧色条高亮。这是会议视觉焦点。
- **下半区 · 大咖意见反馈条（约 35% 高度）**：横向铺满宽度的一排大咖头像卡。每张卡含：头像、姓名/title、当前状态（旁听中/正在发言）、最近一条意见摘要；卡底「发言」按钮。点击按钮 → 该大咖立即表态，卡片高亮"正在发言"，最新意见刷新到卡片摘要并可在字幕区展开。
- **项目简报/进展**：顶部折叠胶囊或一行常驻，不打断字幕流主区。

### 4.2 自动发言逻辑（复用 AI 旁听反馈）
- 转写每累积 ~60s 或检测到话题切换（关键词变化），触发 1–2 位"最相关"大咖。
- 相关性 = 用最近转写命中该角色 `focusPoints` 关键词（沿用 `defense-service.mjs` 的 `keywordRules`）。
- 输出结构：`{ 角色, 严重度, 核心观点, 证据/依据, 建议追问/动作 }`。

### 4.3 手动发言（强制插话）
- 点击头像下「发言」按钮 → 立即以"项目简报 + 最近 N 句转写"为上下文，调用该角色 prompt 生成意见。
- 主持人可随时打断、指定"请 XX 先说"。

### 4.4 散会沉淀
- 自动汇总所有大咖意见 → 按严重度排序 → 生成"决议纪要 + 待办 + 风险清单"。
- 导出 Markdown / PDF；保留完整字幕证据链。

## 七、关键风险与对策
- **安全上下文**：麦克风需 HTTPS 或 localhost；部署时用反向代理挂证书，开发用 localhost。
- **说话人分离**：真实会议多人发言，v1 不做 diarization，统一为一个"会议流"；后续可接带说话人分离的 ASR。
- **API Key 依赖**：未配置时回退本地规则，保证随时可演示。
- **大咖意见质量**：角色 prompt 用 `大咖角色库.json` 的 `persona` + `focus`，叠加"项目简报"作为长期记忆，避免空话；自定义大咖同样走该 prompt 模板。
